# 段边界：台词收口与末帧接力

回答两个问题：台词被截断会不会毁掉衔接？最后一帧到底怎么传给下一段？

2026-11-21 用已有的洛阳桥 50 秒原片做的 0 成本实测，不是推测。

## 一、末帧接力到底是怎么发生的

### 平台的做法

```
段1（0–10s）→ 取最后一帧 → 作为段2 的首帧「条件」
段2（10–20s）→ 取最后一帧 → 作为段3 的首帧「条件」
…
最后一段 → last_image_url 作为它的尾帧
```

文档原话是「每段从上一段的**最后一帧**接着拍」「后面的每一段还会**带上**上一段的末帧」。注意用词：**带上**，不是**贴上**。

### 实测证据（这是最关键的一条）

洛阳桥 50 秒原片，按 24fps 精确取第 958–962 帧（39.92–40.08 秒，第 4 段与第 5 段的交界）：

| 帧 | 画面 |
|---|---|
| 958 | 船在画面左侧、占约 1/3，白衣女子站船头，机位较远 |
| 959 | 与 958 几乎相同（本段最后一帧） |
| **960** | **镜头突然拉近**，船占约 1/2，女子移到画面中央，右侧多出一个蓝衣人物的位置 |
| 961 | 同 960 |
| 962 | 同 960 |

对照四个边界的帧间差异（全片平均帧差 9.04）：

| 边界 | 邻域最大帧差 | 判定 |
|---|---|---|
| 10.0s | 13.0 | 轻微 |
| 20.0s | 6.4 | 平滑 |
| 30.0s | 3.0 | 平滑 |
| **40.0s** | **36.4** | **硬跳（全片最大）** |

**结论：末帧只是「内容延续的提示」，不是「像素级的起点」。** 下一段会延续上一段的人物、场景、光线，但**机位和景别会被重新决定**。所以：

- 边界平滑还是跳，取决于两段的**机位描述是否一致**，跟「末帧传得准不准」关系不大。
- 30 秒边界只跳 3.0，因为那两段机位本来就稳；40 秒跳 36.4，因为第 5 段重新构了个更近的图。

### 你无法指定的东西

- **中间段的末帧**：平台自动抽，我们无法干预、无法预览。
- **段边界的准确位置**：由平台按 duration 平均拆（50 秒 = 5×10，25 秒 = 9+8+8）。位置可算，但内容不可控。
- **能指定的只有两个**：第一段的起始帧（`first_image_url`）、最后一段的终止帧（`last_image_url`）。

## 二、台词被截断会影响衔接吗

**要分成两层看，别混在一起。**

### 图像层：完全不受影响

音轨和画轨是独立的。人声在第 9.8 秒被切，画面照样跑到第 10.0 秒，末帧照样传给下一段。**台词截断不会造成画面断层。**

### 听觉层的真实情况（和直觉相反）

我原以为每个段边界都会断一次话，实测不是。把 50 秒原片的音轨丢给 ASR，时间线是这样：

```
0:01.0 – 0:13.6   这桥若能重建，便利万民……桥基的污泥怕是多年未曾清理了
0:14.3 – 0:23.9   这泥沙混着海水黏得很……
0:25.2 – 0:26.7   喂，岸上的官人
0:27.6 – 0:40.1   船靠岸了，小心脚下……姑娘，收下吧
0:43.1 – 0:49.9   这蛎壳坚固，正可为桥基之用
```

第一句从 1.0 秒一路念到 13.6 秒，**中间跨过了 10 秒的段边界，没有停顿、没有断字**。说明平台拼接时音频是接着走的，模型拿到末帧和 prompt，知道上一句在说什么。

所以：

> **正常写法下（台词量适配段长），模型会自己跨段把话说完，不会断。**
> **真正会断的只有一种情况：你在一段里塞超过 46 字。**

念稿测试那四条（52/65/88/117 字）之所以全断，是我硬塞了超量文字。正常写片子不会这样。

### 唯一的真风险：最后一段的收尾

最后一段没有「下一段」可以接着念，如果台词超出 10 秒，就是整片结尾处的硬切——这是最伤的地方，观众记得最清楚。

## 三、所以怎么写（三条规矩）

### 规矩 1：开口要趁早，余量只留在字上

**不从 0 秒就开口，是纯浪费。** 段长固定 10 秒，头部空白 2 秒等于把台词额度砍掉 20%。实测模型从第一句就开始念、语速稳定在 4 字/秒左右，它不会因为你说"第 2 秒再开口"就准时——时间码它基本不照做，只按字数往下念。

所以：

- **第一句直接进正题**，不要「却说」「话说」「且说那年」这类铺垫。旁白越早进入信息，这一段的信息量越大。
- **不写时间码**（「第 2 秒开口」「第 8 秒收住」）——写了也不照做，还占 prompt 篇幅。只写**字数上限**，不要写「最后一句必须完整」（末句跨界是正常的，见规矩 2）。
- **尾部余量 = 10 秒 − 字数 ÷ 4.0**（按实测语速算；机械核对时按保守的 3.6）。给 36 字，余量约 1 秒；给 30 字，余量约 2.5 秒。余量是算出来的，不是留出来的。
- 段尾那 1–2 秒不写「静音」，写**动作收束**（「镜头停稳，人物停住」）——同一段时间既给了台词余量，又保证了末帧质量（见规矩 3）。一鱼两吃，不浪费。

```
【旁白·画外男声】"<≤36 字，从第一帧就开口>"（画面中无人开口，无口型）
画面随旁白推进：……（动作），末了镜头停稳，构图稳定。
```

### 规矩 2：允许跨段，但别塞满；片尾必须念完

**先说结论：一句话跨过 10 秒边界是正常的，不是错误。** 实测 ASR 显示第一句从 1.0 秒一路念到 13.6 秒，跨过边界没停、没断字——平台拼段时音频是接着走的，模型知道上一句在说什么。

所以**不要为了「每段末句必须完整」去删内容、拆句子**，那是拿叙事换一个不存在的问题。真正要防的只有两个：

1. **一段塞太多字** → 模型不压语速，直接吞句号连读，发音变糊（新筑→新主、桥基→巧计）。
2. **片尾最后一句没念完** → 结尾没有下一段接着念，必定硬切，观众记得最清楚。

判断看三个数，全片当成**一条时间线**，不是 5 个互不相干的盒子：

| 指标 | 舒服 | 偏挤 | 危险 |
|---|---|---|---|
| **单句用量 = 字数 ÷ 容量**（容量 =（下一句开口 − 本句开口）× 语速） | ≤90% | 90–100% | >100%（必改） |
| 本段分配字数（10 秒） | ≤36 | 36–46 | >46 |
| 这段念完离段尾 | 还剩 2–5 秒 | 跨入下一段 1–2 秒 | 跨入下一段 >4 秒 |
| 片尾最后一句结束 | ≤ 片长 −1 秒 | 片长 −0.8~−1 秒 | > 片长 −0.8 秒 |

**一段说不完怎么办：少说一句，剩下的挪到下一段开头。** 三种做法，优先级从高到低：

1. **砍内容**——这一拍本来就不需要那么多话。删形容词、删观众已经看见的东西（「船头立着一位白衣女子」→ 画面里有，就别念）。
2. **挪到下一段开头**——这一拍只讲到一半，下一拍第一个字接着讲。跨段是允许的，只要别让上一句占到下一段一半以上的时间。
3. **换更短的句子**——用短句替代从句，同样的信息量少 30% 字。

**绝不做**：加「语速快一点」这类形容词，或者靠留静音腾时间。它不听，只会念到时间用完然后斩断。

```
【旁白·画外男声】"<≤36 字，从第一帧就开口；宁可少说，别塞满>"（画面中无人开口，无口型）
```

### 规矩 3：段尾不许有大动作，机位要和下一段一致

末帧就是下一段的起点。**段尾正在做的事，会被下一段放大或重演。**

- ❌ 段尾写「官员猛地转身冲出画面」→ 末帧是运动模糊，下一段从糊帧开始
- ❌ 段尾写「镜头快速摇向江面」→ 末帧是拖影
- ✅ 段尾写「动作收束，人物停住，镜头停稳，画面清晰」
- ✅ 相邻两段用**同一句机位描述**（如「中景，平视，机位固定」），边界跳变会小得多

## 三·五、写完台词必跑一次机械核对（v3：按开口时刻算容量）

靠眼睛数字数一定会漏。台词先写成台词卡（一行一句），交给脚本判：

```bash
python ~/.workbuddy/skills/muse生视频/scripts/check_words.py 台词卡.txt --seg 10 --segs 5
```

台词卡格式（`段号|角色|文本[|起秒][|语速档]`）：

```
1|旁白|洛阳江入海口，水阔五里，潮水一日两至。蔡襄到任那年，江上无桥。
2|蔡襄|潮水一日两至，这石基如何立得稳？|1.2|紧
2|老匠|大人，江底烂泥，石头沉底。|快
```

- 第 4 列可写**起秒**（`2|蔡襄|……|1.2`），也可直接写**档名**（`|快`）；写起秒时要给第 5 列档名。
- 不给起秒：同段紧接上一句念完的时间，同段第一句从段首 0 秒开口。
- **不写档名 = 稳档（3.6 字/秒），并且这一段 36 字封顶。** 写了 39 字就是错——不许「没设语速但赌它念得快」。
- 档位：稳 3.6 / 快 4.0 / 紧 4.4 / 极限 4.6（>4.6 判错，实测必糊音）。

输出三张表：

1. **逐句核算**：每句的字数 / 档位 / 开口→念完 / 硬截止 / 窗口 / 容量 / 用量。核心是那句——
   > 「从 0.0s 开口，老匠要在 13.9s 开口，按稳档 3.6 字/秒只剩 10.0s 能说 36 字；你写了 39 字（多 3 字）」

   这就是「从啥时候开始说、还能说多少」的直接答案，**不是按条数算**。
2. **逐段汇总**：首句开口时刻 / 段内字数 / 密度 / 收尾（正数=距段尾还剩多少）。
3. **必须改 / 提醒**：超容量、无档位却超 36 字、>4.6 字/秒、片尾截断 → 必改；头部开口晚于 0.5 秒、跨段 >4 秒 → 提醒。

返回码非 0 就还有必须改的项。优先级：**片尾 > 超容量（撞车）> 密度**——这个顺序就是观众的感受顺序。

## 四、后期兜底（0 成本）

### 先判断要不要修

```bash
ffmpeg -v error -i in.mp4 -vf "fps=24,signalstats,metadata=print:key=lavfi.signalstats.YDIF:file=-" -f null - \
  | grep -o "YDIF=[0-9.]*" | cut -d= -f2 | python -c "
import sys
v=[float(x) for x in sys.stdin.read().split()]
avg=sum(v)/len(v)
print('平均帧差 %.2f' % avg)
for b in [240,480,720,960]:
    if b<len(v):
        m=max(v[b-2:b+2])
        print('边界 %ds 最大帧差 %.2f  %s' % (b//24, m, '需处理' if m>avg*2.5 else '可接受'))
"
```

- 边界帧差 **< 2.5 × 平均** → 不用管，观众看不出
- 超过 → 人工看那两帧，决定叠化还是重写 prompt 重出该段

### 叠化遮掉跳变 + 顺带遮掉断句

段边界做 0.25 秒交叉溶解，画面上像正常剪辑点，听觉上断话也被垫掉。要处理 40 秒那一处：

```bash
# 拆成 0–39.875 和 40–50 两段，中间 0.25 秒叠化
ffmpeg -y -i in.mp4 -filter_complex "
[0:v]trim=0:39.875,setpts=PTS-STARTPTS[a];
[0:v]trim=40:50,setpts=PTS-STARTPTS[b];
[a][b]xfade=transition=fade:duration=0.25:offset=39.625[v];
[0:a]atrim=0:39.875,asetpts=PTS-STARTPTS[aa];
[0:a]atrim=40:50,asetpts=PTS-STARTPTS[bb];
[aa][bb]acrossfade=d=0.25[ao]" \
  -map "[v]" -map "[ao]" -c:v libx264 -crf 18 -c:a aac -b:a 192k out.mp4
```

代价：整片短 0.25 秒。多段多处处理会累积，所以**能靠 prompt 解决就别靠后期**——重出一段 ¥0.2，叠化是免费的但每处都要掉时长。

## 五、验收清单（针对这两个问题）

1. **每个段边界抽 ±2 帧**，算帧差，>2.5×平均就人工看。
2. **ASR 对齐台词时间线**：中间段末句跨过边界属正常，不必修；只看**片尾**最后一句有没有说完。
3. **段尾帧**单独看一眼，确认不是运动模糊、不是黑帧、不是大特写。
4. **最后一段倒数第二句**重点听，这是最容易被切的地方。
